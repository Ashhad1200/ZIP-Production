🔐 Authentication Flow

Kiosk-mode login — no passwords. User selects their name from a list. JWT stored in httpOnly cookie.

Login Flow

1. User opens login page

Frontend calls GET /auth/users (public) → shows list of 6 user tiles

2. User clicks their name

Frontend calls POST /auth/login { userId } with the selected user's UUID

3. Backend validates

Check: user exists? → user.isActive? → if NO → 401 UNAUTHORIZED

4. Generate JWT token

Payload: { userId, role, name } · Secret: JWT_SECRET · Expires: 24h

5. Set httpOnly cookie

Name: token · HttpOnly · Secure (prod) · SameSite: Lax · MaxAge: 24h
Cookie auto-sent with every subsequent request via withCredentials: true

6. Redirect to Dashboard

React Router navigate('/') → ProtectedLayout renders based on role

Every Protected Request

Browser sends request

Cookie token=JWT automatically included

authenticate middleware

Extract token from req.cookies.token → verify JWT → attach req.user = { userId, role, name }

RBAC middleware

Check req.user.role ∈ allowedRoles[] → if NO → 403 FORBIDDEN

Controller executes

Business logic runs with req.user context for audit trail

⚙️ Production Entry Flow

Creating a production entry triggers raw material consumption, finished goods stock increase, and electricity monitoring.

POST /production/entries

Input: plantId, shift (DAY/NIGHT), date, variantId, metersProduced, gramsPerMeter, electricityUnitsConsumed, workersPresent, scrapWeightKg

Validate uniqueness

Check (plantId + shift + date) combination doesn't already exist → if duplicate → 409 CONFLICT

Calculate raw material consumption

gramsConsumed = gramsPerMeter × metersProduced
bagsConsumed = gramsConsumed ÷ grainType.bagWeightGrams

Check raw material stock

If rawMaterialStock.currentBags < bagsConsumed → THROW "INSUFFICIENT_RAW_MATERIAL"

⚡ Deduct raw material stock

rawMaterialStock.currentBags -= bagsConsumed

⚡ Increase finished goods stock

finishedGoodsStock.currentMeters += metersProduced (upsert for variant)

Check electricity discrepancy

Compare actual vs expected (machine KWh × shift hours). If deviation > 15% → flag hasElectricityDiscrepancy = true → notify SUPER_ADMIN

Create production entry record

Store all data + version=1 + create audit log

Automated Side Effects

  • Raw material stock decremented (bags consumed)
  • Finished goods stock incremented (meters produced)
  • Low stock notification sent if below threshold
  • Electricity discrepancy flagged + notification if >15% deviation
  • Audit log entry created

Scrap Sale Flow

Calculate total

totalAmountPaisa = totalWeightKg × ratePerKgPaisa

⚡ Create journal entry (auto-posted)

DEBIT Cash · CREDIT Scrap Revenue

🚛 Gate Pass Flow (Core Transaction)

The most complex transaction — dispatching goods. Creates ledger entries, deducts stock, updates orders, generates QR verification tokens.

POST /gate-passes

Input: clientId, date, shift, lineItems[{variantId, meters}], vehicleNumber, driverName, orderId (optional)

🔒 Begin database transaction

All following operations are atomic — either ALL succeed or ALL rollback

Validate each line item

For each variant: check stock sufficiency → look up active client rate → if no rate found → THROW "RATE_NOT_FOUND"

Calculate amounts

Per line: lineAmount = ratePerMeterPaisa × meters
Total: totalAmountPaisa = Σ lineAmounts
Due date: gatePassDate + client.paymentCycleDays

⚡ Deduct finished goods stock

finishedGoodsStock.currentMeters -= meters for each variant line

⚡ Create journal entry (auto-posted)

DEBIT Accounts Receivable (client) → CREDIT Sales Revenue
Revenue recognized immediately on dispatch

Generate gate pass #, QR verify token

Sequential: GP-YYYY-NNNNN
Crypto-random 64-char hex token, expires in 48h

If linked to order?

YES → update order.metersDelivered += totalMeters
If metersDelivered ≥ metersOrdered → set order status = COMPLETED

✅ Commit transaction + return gate pass

GP number, line items, total amount, payment due date, verify token

Automated Side Effects (all atomic)

  • Finished goods stock decremented per variant
  • Journal entry POSTED (AR debited, Revenue credited)
  • Payment due date calculated (client.paymentCycleDays from GP date)
  • Order fulfillment updated (if orderId linked)
  • QR verify token generated for physical verification
  • Audit log created

📦 Order Flow

Orders track client demand. NO journal entry at creation — revenue recognized only when gate pass issued (dispatch).

POST /orders

Input: clientId, variantId, metersOrdered, ratePerMeterPaisa, deliveryDeadline

Validate & calculate

Client exists? Variant exists? Deadline in future?
totalAmountPaisa = metersOrdered × ratePerMeterPaisa

Generate order # (ORD-YYYY-NNNNN)

Status = PENDING, metersDelivered = 0

⚡ Notify PRODUCTION_HEAD

Notification includes: order #, client, variant, meters, deadline
⚠️ Financial data (rate, total) is EXCLUDED from notification

Order Fulfillment (via Gate Passes)

PENDING
metersDelivered = 0
→
IN_PROGRESS
partial deliveries
→
COMPLETED
delivered ≥ ordered

Each gate pass linked to an order auto-increments metersDelivered. When threshold met → status auto-updates to COMPLETED.

💰 Finance Flows

Payment Recording

POST /finance/clients/:clientId/payments

Input: amountPaisa, date, paymentMode (CASH/CHEQUE/BANK_TRANSFER), chequeNumber, notes

⚡ Create journal entry (auto-posted)

DEBIT Cash/Bank (1000) → CREDIT Accounts Receivable (client)
"Payment received from {clientName}"

Calculate new outstanding

outstanding = Σ(client debits) - Σ(client credits)
Returned to frontend for display

Voucher Creation & Auto-Approval

POST /finance/vouchers

Input: title, amountPaisa, date, categoryId, companyId, paymentMode, chequeNumber

Amount check: ≤ PKR 2,00,000?

✅ YES (≤ 20M paisa) → AUTO_APPROVED

❌ NO (> 20M paisa) → PENDING → notify SUPER_ADMIN

If auto-approved: ⚡ Create & POST journal entry immediately

DEBIT Expense (5000) → CREDIT Cash/Bank (1000)

If pending: awaits SUPER_ADMIN action

PATCH /finance/vouchers/:id/approve { action: "APPROVE" | "REJECT" }
APPROVE → creates JE and posts it · REJECT → no JE created

Client Ledger View

GET /finance/clients/:clientId/ledger — Shows chronological debit/credit entries with running balance.
Debits come from gate passes (goods dispatched to client), credits from payments received.
Outstanding = totalDebits − totalCredits. Overdue = unpaid past due date.

📊 Inventory Flow

Finished Goods Stock (Zipper Meters)

📈 Stock Increases When:

  • Production entry created — metersProduced added

📉 Stock Decreases When:

  • Gate pass created — meters per line item deducted

Raw Material Stock (Grain Bags)

📈 Stock Increases When:

  • Raw material purchase recorded — bags added

📉 Stock Decreases When:

  • Production entry created — bags consumed (gramsPerMeter × meters ÷ bagWeightGrams)

Raw Material Purchase Flow

POST /inventory/raw-materials/purchases

Input: grainTypeId, numberOfBags, ratePerBagPaisa, purchaseDate, source

Calculate total

totalAmountPaisa = numberOfBags × ratePerBagPaisa

⚡ Create journal entry (auto-posted)

DEBIT Raw Material Inventory (asset) → CREDIT Cash

⚡ Increment raw material stock

rawMaterialStock.currentBags += numberOfBags
